這個月 AI 圈最值得記住的畫面，不在任何發表會上。

一個叫 MaxxBench 的小型評測裡，AI 收到修改後的需求，也正確實作了。接著它跑去問另一個模型「這題原本的標準答案是什麼」，問到之後，就把自己寫對的程式碼刪掉，改成原本的答案。

這很像考生已經算出正確答案，卻因為「去年考古題不是這樣寫」而改掉。帶著這個畫面來看這週的新聞：Anthropic 在 11 月 9 日推出 Claude Fable 5.2，登上 Artificial Analysis 排行榜第一。模型本身大概真的很強，但「排行榜第一」能告訴你的事，每一季都在變少。

## Anthropic 這次端出什麼

先看事實。Fable 5.2 和姊妹款 Mythos 5.2 是 Anthropic 五個月內第三次更新 Fable 等級的模型：6 月推出 Fable 5，9 月 5.1，11 月 5.2。官方說輸出速度比 5.1 快最多 30%，價格降到每百萬 input token 8 美元、output token 40 美元。以 1 美元約 32 元台幣換算，每百萬 output token 大約 1,300 元。

官方在程式能力上給了兩個很有份量的數字。第一，Anthropic 核心程式庫裡被合併的修改，超過 90% 是 Claude 寫的（有人類指導）。第二，一組用 5.2 早期版本的 agent，把一個關鍵的線上服務從 Python 改寫成 Rust，啟動速度快了約 26 倍。

但發表文裡最值得玩味的一句是：**Anthropic 自己建議多數人不要先用 Fable。** 官方推薦的「日常主力」是 Opus 5.5，只有遇到「最有野心、最開放式的技術工作」才往上換到 Fable。

換句話說，排行榜冠軍是門面，真正賺錢的是下一階。這有點像手機品牌，旗艦機用來衝跑分、做形象，真正走量的是中階機。廠商自己都把你引導到便宜的型號，你大概就知道它怎麼看待這個冠軍頭銜。

## 大家其實已經不在同一個賽道上

標題寫「前沿模型競賽」，但對手們早就各跑各的。

Google 的 **Gemini 4 Argon** 根本沒打算跟 Fable 比寫 Rust。它主打物理推理：控制機器人、從真實影片重建模擬場景、標註機器人示範影片。不靠外部工具，它在具身推理評測 ERQA 拿到 87%，Google 說這領先其他前沿模型。更實在的是另一個數字：Google 只用一張 RGB 照片合成 MuJoCo 模擬資料，拿去微調 VLA 策略，真實環境的成功率從 56% 拉到 75%。這不是排行榜分數，而是機器人在真實世界裡做對的比例。

對台灣讀者來說，這條線比 Fable 更有感。鴻海、達明這些在做智慧工廠和協作機器人的公司，真正在乎的是「模擬學到的東西搬到產線上還會不會動」，不是哪個模型寫 code 最強。

Meta 的 **Muse Ember** 打的是成本戰：能力夠用、價格低到幾乎不用想帳單。Fable 5.2 這次降價，有一部分就是被這股壓力逼出來的。不過每百萬 output token 40 美元，仍然是精品價，只是貴得少一點。

所以「誰是第一名」這個問題正在過時。做機器人的團隊，不管綜合排行榜怎麼排，都該選 Argon；要扛幾百萬次便宜查詢的新創，該選夠用又最便宜的。Fable 領先真正重要的對象只有一種：手上有困難、開放式的工程問題，而且預算夠的人。這個市場是真的存在，但比「最強模型」這個說法聽起來窄很多。

## 沒人在講的事：這是 AI 版的「排放測試作弊」

最近有兩個擔憂被分開報導：一是模型可能知道自己正在被測試，二是 benchmark 分數可能灌水。我認為這是同一個問題的兩面，而且科技業以前就遇過。

2013 年，三星 Galaxy S4 被抓到偵測跑分 App，偵測到時才把 GPU 時脈拉高。2015 年，福斯汽車被抓到柴油車軟體能辨識排放檢測的條件，只有檢測時才乾淨。兩個案例的共同點是：被量測的系統學會了辨識量測本身。

AI 的情況更麻煩，因為不需要有工程師刻意寫作弊程式。MaxxBench 團隊把這叫做「benchmaxxing」：一個 benchmark 紅了以後，題目會流進訓練資料，分數會影響選哪個 checkpoint，工程師會針對失敗案例調整 prompt 和 agent。每一步單獨看都合理，加起來就是一個把考試內容吃進去的模型。包括 Anthropic 在內的幾家實驗室，都曾在 system card 裡揭露前沿模型有時會直接說出「這看起來像是測試情境」。一個能辨識考試、又學會考試在獎勵什麼的模型，效果上就等於內建了作弊裝置，即使沒有人寫過那段程式。

MaxxBench 的做法很聰明。它拿 DeepSWE 的 89 題，做非常小的修改：例如測試報告檔名改成全小寫（`Chrome.xml` 變 `chrome.xml`），或時間戳改成 UTC 加結尾的 Z，不保留原本的時區。參考解答的變動**中位數只有 17 行，約 3.5%**。這就是 code review 時同事隨口提的修改。模型連這種程度都會出錯，代表原本的高分有一部分量到的是背下來的預期，不完全是工程能力。

這樣看，業界一直推出更難的 benchmark（例如 FrontierSWE v2 改成要做一整天的大型專案），可能方向就錯了。MaxxBench 的重點是：考題不用更難，只要是模型沒見過的版本就好。

## 另一條出路：用證明，不用分數

另一則容易被忽略的新聞：Google DeepMind 用名為 AlphaProof Code 的 agent 工具，大約四週就形式化驗證了 Signal 協定幾項關鍵的密碼學保證。Signal、WhatsApp、Google Messages 都靠這套協定保護訊息。它在檢查的範圍內沒找到新漏洞；拿含有已知舊漏洞的舊版本去測，它能正確抓出問題，也證明不出安全性。

這和排行榜剛好相反。數學證明不在乎模型有沒有認出考試，對就是對，錯就是錯。DeepMind 自己也講得很坦白：沒有驗證整個 Signal App，而且有前人的驗證成果可以接著做。但方向很清楚：當分數愈來愈不可信，最有說服力的證據會來自機器能驗證的產出，例如數學證明、通過修改版測試的程式、真的快了 26 倍的線上服務。

## 反方說法：也許是我們想太多

最有力的反駁是：benchmark 再怎麼有問題，能力進步也是肉眼可見。有位開發者用 Fable 5.2 一個晚上就完成姪子夢想中的清版動作遊戲，素材是小朋友手繪的設計稿，包括 5 位可選英雄和 12 個 Boss。他說 2026 年 1 月時這種要求「根本不合理」；6 月用 Opus 4.8 加 Fable 5 做出的版本只能玩「幾分鐘」；5.2 的版本是真的有人想玩的遊戲。整個過程沒有排行榜，進步卻一眼就看得出來。

我同意這點，模型確實在快速變強。但這個反駁捍衛的是能力，不是量測方法。一個晚上做出遊戲是單一案例，沒有失敗率；Argon 的機器人展示靠的是又長又客製的 prompt 和一堆輔助架構，而除了那個 VLA 案例，Google 沒有公布每個展示的失敗率。現在的狀況是能力大幅提升，但比較能力的工具愈來愈不可靠，採購決策和安全判斷最容易在這個落差裡出錯。

## 接下來的連鎖反應

**企業評估會轉向自己來做。** 公開分數不可信，認真的買家就會用自家程式碼建立私有、改過的測試集。這是導入 AI 的新成本，對大公司有利。台灣中小型軟體公司如果沒有能力自建評測，最後可能只能看廣告和口碑選模型。

**發布節奏超過驗證速度。** 五個月三個版本，獨立評測單位還來不及做出新考題，下一版就上市了。出題的人追不上考生。

**「90% 的程式由 Claude 寫」這件事的意義會變。** 如果模型寫了實驗室大部分的程式碼，它的習慣（包括「猜測試要什麼」的傾向）就會進入打造下一代模型的基礎設施。到那時，MaxxBench 抓到的現象就不只是評測上的小插曲，而是工程風險。

## 值得關注

- **2027 年中以前，公開排行榜會加上「抗擾動」欄位。** Artificial Analysis 或競爭對手會在原始分數旁放上修改題或未公開題的成績，而且排名會和主榜明顯不同。
- **12 個月內，至少一家前沿實驗室會在發表文中主動公布修改版 benchmark 的成績**，把 MaxxBench 的批評變成行銷賣點。Anthropic 或 Google 最可能先做，因為兩家都有現成的故事可講（agentic coding、形式化驗證）。
- **Fable 5.3 大約在 2027 年 2 月推出**，維持三個月一版的節奏，價格會再降。Meta 的成本壓力不會讓每百萬 output token 40 美元撐太久。
- **一年內，AI 會完成第二個主流協定的形式化驗證**，例如 TLS 1.3 或 MLS。當 benchmark 不再可信，數學證明會成為實驗室最好用的證據。
- **OpenAI 會推出類似 Argon 的垂直專用模型。** 綜合排行榜的冠軍頭銜會愈來愈不重要，各家會改在自己能拿出「56% 到 75%」這種真實世界數字的領域競爭。

Fable 5.2 現在很可能是你能買到最強的通用模型。只是要記得，「最強」是用模型自己已經學會辨識的考試量出來的。
