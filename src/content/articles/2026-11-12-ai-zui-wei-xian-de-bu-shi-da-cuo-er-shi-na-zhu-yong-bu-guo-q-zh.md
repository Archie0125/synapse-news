大家都在擔心 AI 會不會變得太聰明，企業卻正在犯一個更低級的錯：把正式環境的永久密碼交給一套本來就可能看錯、聽錯、被誘導的軟體。

真正危險的 AI agent，不一定是能力最強的那一個，而是同時拿著資料庫、GitHub、雲端硬碟與付款系統權限的那一個。模型偶爾答錯並不稀奇；可是一旦「答錯」後面接著自動執行，錯誤就會從聊天視窗一路穿透到公司帳務、客戶資料與正式環境。

不少團隊仍用十年前設定排程程式的方式部署 agent：把 `DATABASE_URL`、Stripe 金鑰或組織層級的 `GITHUB_TOKEN` 塞進環境變數，再於 system prompt 寫上「只准修改測試資料」。問題是，prompt 只是在描述期待，token 才是在定義權力。前者是公司守則，後者是萬能鑰匙；攻擊者在乎的從來不是守則。

這也是為什麼「模型有沒有遵守指示」根本不是合格的安全邊界。Agent 每天主動讀取 Email、客服單、網頁、PDF、程式碼與第三方 API 回傳內容，其中任何一項都可能夾帶 prompt injection、惡意套件說明或刻意設計的誤導文字。如果讀取外部內容的程序，同時保管可長期存取正式系統的憑證，一次解析失誤就足以變成跨系統事故。

合理的設計其實很樸素：agent 先提出動作，由另一個獨立的政策服務檢查對象、金額、範圍與時效，再簽發只能使用一次的短效授權。例如，「30 秒內退款 29.50 美元給訂單 4821」與「永久擁有整個 Stripe 帳號的退款權」看似都能完成工作，事故半徑卻完全不同。一次性 nonce 用完即失效；主金鑰留在 agent 程序之外；每次操作都留下可核對的簽章紀錄。即使模型失控，也只能做完那一件已核准的事。

最小權限並不是 AI 時代的新發明。Saltzer 與 Schroeder 早在 1975 年就已整理出這項原則。現在不同的地方，是軟體不再只是沿著工程師預先寫好的路徑執行，而是由模型臨場決定下一步：先讀 Slack，再查 Salesforce，接著改 GitHub，最後寫回雲端硬碟。每多串接一個服務，身分、授權與上下文發生誤判的機會就再增加一層。

[Grok Build 的資料外洩案例](https://www.engadget.com/2313187/grok-build-leaked-sensitive-spacexsi-data/)很能說明問題有多麼不「高科技」。它產生的分享連結使用四個隨機單字，最高約有 38 bits 的熵，看起來不容易猜中；但隨機字串被放在網域左側，可能被被動 DNS 系統記錄，而不是像一般私密分享連結那樣放進網址路徑。換句話說，密碼強度不是問題，密碼被寫在公開簽到簿上才是問題。

Claroc 表示，這類被稱為 GhostShares 的頁面暴露了數千名使用者的資料，牽涉醫療組織、消防單位、六家《財星》500 大公司，以及 26 家員工超過 1,000 人的企業。SpaceXSI 自己外露的內容包括 594 個策略客戶的業務地圖、八份 X 廣告提案、四個仍在使用的廣告主看板，以及兩份品牌安全手冊。只有一個 app 要求密碼；Claroc 估計約 2% 的內容達到高風險或嚴重等級。

2% 聽起來不多，卻正是平台規模化之後最麻煩的數字。假設一家公司讓員工用 AI 建立 10,000 個小工具、資料看板與分享頁面，2% 就是 200 個可能涉及敏感內容的入口。測試階段多數頁面沒有重要資料，因此錯誤預設看似無害；真正上線後，少數高價值資料會被埋在大量低價值內容裡，直到搜尋引擎、DNS 資料庫或研究人員替你找到。

SpaceXSI 在事件公開升高後移除了自家 24 個 app，但報導指出，其他使用者留下的 app 並未一併處理。這揭露了 AI 平台常見的責任轉嫁：平台設計了不安全的分享機制，善後卻交給每一位使用者自行發現、自行刪除。若安全必須靠所有人都不犯錯，那就不是安全設計。

英國政府的案例更直接。一名研究人員使用 Claude Opus 與 Sonnet，在公開程式碼中找到[超過 100 個嚴重漏洞](https://www.wired.com/story/security-flaws-across-uk-government-sites-exposed-god-tier-information/)。最嚴重的一項，是 Microsoft Entra ID 登入憑證曾被放上 GitHub，後續又沒有完整撤銷。該權限據稱可讀寫所有 SharePoint、員工私人 OneDrive、HR 紀錄，以及依法保全的都市規劃案件證據，研究人員形容它是「god-tier」權限。

Planning Inspectorate 表示，監控系統有偵測到研究活動，接獲通報後 20 分鐘內完成修正，並確認沒有資料遭入侵。這值得肯定，但也反過來證明前面的防線有多薄：憑證範圍過大、撤銷不完整、原始碼公開後缺乏持續檢查。Claude 讓弱點更快被看見，弱點本身卻只是傳統 IT 健檢就該抓到的問題。

AI 的確可以加快找洞，但找到洞不等於修好洞。Anthropic 的 Project Glasswing 執行七個月後，[VulnCheck 統計到 37,966 項回報](https://www.vulncheck.com/blog/anthropic-glasswing-november-update)，其中只有 7,349 項、也就是 19.4% 公開，標記為已修復的更只有 217 項。自 9 月以來，新增近 12,000 項發現，修復數卻只增加 15。另有 1,654 項重複回報與 419 項撤回；curl 維護者在 34 項公開回報中，拒絕認定其中 19 項為漏洞，六項只列低風險，九項仍待判定。

反方說法並非沒有道理。VulnCheck 追蹤到歸因於 Anthropic 的 CVE 是 442 個，約占當年度公開 CVE 的 0.5%，確認遭實際利用的只有兩個。這距離「AI 自動掃描將徹底改寫資安」的宣傳還很遠。Anthropic 宣稱的 true positive rate 從 90.8% 上升至 94.2%，但如果重複、撤回與維護者拒絕的案件沒有被一致計算，漂亮百分比就只是行銷版儀表板。

然而，這並不表示風險被誇大，反而點出另一個更現實的缺口：機器製造警報的速度，已經超過人類驗證與修補的速度。當系統增加 12,000 項發現，修復卻只增加 15 項，維護者得到的可能不是更安全的軟體，而是一個更吵、更難排序的待辦清單。資安團隊缺的不是第 37,967 封通知，而是可重現證據、去重、風險排序、明確負責人與修補工時。

同樣的驗證問題也已經落到消費者身上。Podqi 測試了 [6,795 次購物問答](https://www.theverge.com/ai-artificial-intelligence/1032020/gemini-chatgpt-perplexity-shopping-test-risky-fake-websites-citations)：Perplexity 有 15% 的回答出現高風險網址，ChatGPT 為 8%，Gemini 為 4%。這些網址包括仿冒商店、販售假貨的網站、被他人重新註冊的品牌舊網域，以及已失效但可重新購買的網域。ChatGPT 即使列出危險網站，也只有 24% 的情況會附上警告。

這項研究也有侷限：問題由研究者設計，不是取自真實使用者對話；受測品牌 Madhappy 還是 Podqi 的客戶。可是，就算採用最低的 4%，也不能當成可忽略的誤差。搜尋引擎列出十個結果時，使用者還會看網址、比較來源、注意警告；聊天機器人用一句肯定語氣說「你可以在這裡買」，等於把原本分散的風險訊號壓縮成單一推薦。

台灣消費者尤其該注意這一點。在 momo、PChome 或蝦皮購物時，至少還看得到賣家評價、退貨流程、平台付款與到貨紀錄；AI 若直接把人送往陌生品牌官網，這些保護會同時消失。接下來只要再加上自動填地址、信用卡與一鍵結帳，錯誤連結就不再只是資訊品質問題，而是付款與個資外流問題。

這裡有一件幾乎沒人在談的事：AI 回答正在成為網路的「身分驗證層」，卻沒有承擔身分驗證的責任。模型一旦說某網址是 Birkenstock、Lululemon 或 Le Creuset 的可信通路，多數使用者不會再查 WHOIS、網域註冊日期或品牌官方名單。詐騙者也不必在 Google 搶到第一名；他只需要讓假網域出現在模型會讀取的資料裡，並等待 AI 替它背書。

Podqi 的測試還發現，小型品牌出現危險網站的機率約是大型品牌的兩倍。這會產生第二層效應：大型品牌有法務、品牌保護與搜尋團隊，可以快速處理仿冒網域；台灣中小企業、地方店家與跨境小眾品牌往往沒有。AI 購物愈普及，最缺乏防禦資源的商家，反而最容易被假網站截走訂單與信任。

因此，企業不該再用「模型通常會聽話」當作 agent 上線標準。每個會改資料、花錢、寄信、發布程式或調整權限的動作，都應該有可驗證的對象、最小化授權、金額或筆數上限、明確期限，以及完整操作收據。紀錄至少要回答五件事：誰提出動作、模型看到什麼、哪條政策放行、簽發了什麼權限、最後實際發生什麼。事故後若無法重建這條鏈，公司部署的就不是助理，而是一名沒有打卡紀錄、動作速度又快上千倍的員工。

## 值得關注

- **永久憑證會從「技術債」變成稽核缺失。** 2027 年底前，大型企業採購 AI agent 時，將開始要求分鐘級到期、單次動作授權與 agent 程序之外的政策檢查。只靠 system prompt 限權的產品，會先被金融、醫療與政府標案刷掉。

- **漏洞數量不再是值得炫耀的 KPI。** Glasswing 這類計畫將被迫公開維護者接受率、重複率、撤回率、修復時間中位數與實際遭利用比例。找到 10,000 個問題卻只修 15 個，最後只會被視為製造工單。

- **ChatGPT、Gemini 與 Perplexity 會被迫做品牌網域驗證。** 下一步不只是顯示引用來源，而是檢查網域年齡、所有權異動、官方授權名單與重新註冊紀錄。陌生商店若要進入自動結帳流程，必須先通過額外確認。

- **第一批代表性的 agent 訴訟，不會是 AI 逃出實驗室。** 爭議將是模型拿著合法憑證，執行了未被真正授權的退款、刪除、寄信或採購。能提出單次授權與完整操作收據的公司，至少能說清楚責任；只剩 prompt 紀錄的公司，只能解釋當初為什麼相信一句「請小心操作」。
